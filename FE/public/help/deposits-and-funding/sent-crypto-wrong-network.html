I sent crypto on the wrong network — what happens now?

It depends entirely on which network you used — some wrong-network deposits can be recovered manually, and some are permanently and unrecoverably lost.

The honest answer

Blockchain transactions are irreversible. Once a transfer is confirmed, it cannot be cancelled, reversed or recalled — not by you, not by Betabase, not by anyone. What matters now is whether Betabase happens to control the private key for the address you sent to, on the network you used.

  • Sometimes recoverable. If you sent an asset on a network Betabase supports, to an address we control on that network — for example a token sent to an EVM address that is valid on several EVM chains — a manual recovery may be possible. It is a slow, engineering-led process, may carry a recovery fee, and is never guaranteed.
  • Not recoverable. If you sent to a network Betabase does not support at all, or to an address type nobody holds the key for, the funds are gone. No support ticket, tool or paid "recovery service" can bring them back.

Steps

  1. Stop. Do not send anything else to the same address.
  2. Find the transaction hash (TXID) in your sending wallet.
  3. Confirm on a block explorer which network it actually went out on, and that it is confirmed.
  4. Contact support@www.betabase.pro with: the TXID, the exact asset and token contract, the network used, the intended network, the destination address, the amount and the date.
  5. Wait for the assessment. Do not open duplicate tickets — it slows the queue, not speeds it.

How to never do this again

  • Always select the network in Betabase first, then match it in the sending wallet.
  • Always send a small test amount before a large transfer.
  • Copy addresses with the copy button. Verify the first and last four characters.

Anyone contacting you offering to "recover" lost crypto for an upfront fee is a scammer, without exception. Betabase will never ask for your password, 2FA code, seed phrase or private keys.
